## 1. What changed since the partition-only build

The [prior faceted build](../../../../TODO.md) (§16.4i) established the
**functional partition** — power stage on Panel P, logic/comms on Panel L,
19-net signal-only interconnect — but placed nothing. This build runs
[`docs/tools/facet_placement.py`](../../../../docs/tools/facet_placement.py)
against that same partition to produce real footprint placement.

```text
Panel P (power stage): 30 parts, 23.00 x 89.51 mm
  rotated 90 deg to fit strip width: SH1
Panel L (logic/comms):  35 parts, 23.00 x 61.68 mm
```

**SH1 fits — by rotation, not by re-selection.** The Faraday shield can
(Würth WE-SHC 3670209) is 22.75 × 17.15 mm. Un-rotated, 22.75 mm against a
23.00 mm strip left 0.25 mm total margin — not workable, per `TODO.md`
16.4e. Rotated 90°, it presents **17.15 mm** across the strip (5.85 mm of
margin) and 22.75 mm along the panel's length, which the shelf-packer
already has room for. This is placement, not a redesign: the can's PCB
footprint pads are symmetric enough that a 90° rotation does not change
which nodes it shields — but **the physical shielding geometry after
rotation has not been re-verified against the switching node it must
cover**, and that check is still open (see §4).

## 2. Panel envelopes, as placed

| | Panel P | Panel L |
| --- | --- | --- |
| Parts | 30 | 35 |
| Strip width | 23.00 mm | 23.00 mm |
| Length (component-driven) | 89.51 mm | 61.68 mm |
| Combined envelope (side by side, 3 mm gap) | 49.00 × 89.51 mm | |

**Length is the component-driven dimension**, exactly as the Form Factor
axis's `Component-Driven Dimension` column describes: width was pinned at
23.00 mm and the parts then set how long each panel had to be. Panel P is
longer than Panel L primarily because of SH1's rotated 22.75 mm run and the
six FET packages, which do not tile as densely as the smaller logic
passives.

**These lengths are a placement floor, not a routed length.** The
shelf-packer is a simple greedy row-packer (largest-area-first, no routing
awareness); it proves the parts fit and gives real numbers, but a
routing-aware placement pass will very likely produce different lengths
once track and clearance requirements shape the packing.

## 4. What is not done

- **Routing, stackup, copper.** No track, via, or zone exists on this board
  — they were all deliberately stripped from the flat parent's geometry,
  which did not apply to this layout. `TODO.md` 15.2 (stackup) is
  unresolved and gates real copper.
- **SH1's rotated shielding geometry is unverified.** Rotating the can
  changes which board area its skirt covers relative to the switching node
  it exists to shield. This needs a real check against the gate-drive loop
  once Panel P's power-stage internals (Q1–Q6, U5) are placed relative to
  it — right now the shelf-packer places SH1 as just another rectangle by
  area, with no awareness of what it must physically enclose.
- **Interconnect part.** No connector, busbar, or flex chosen (19 signal
  nets, per the parent partition build).
- **Panel length is not routing-aware** (§2).
- **Host envelope confirmation** (`TODO.md` 16.3) — R = 30 mm and the
  2.5 mm depth budget are the owner's figures; the ~90 mm and ~62 mm panel
  lengths have not been checked against the nacelle's internal length.
- **Mounting scheme** (`TODO.md` 16.4h) — still the item that decides
  vibration survival for either faceted option, still with no owner.

## 5. Reproducing this placement

```bash
python3 docs/tools/facet_placement.py \
    --board builds/6s/50A/CAN_485_faraday_sameend/kicad/open_secure_esc_6s_50a_can485_faraday_sameend.kicad_pcb \
    --output kicad/open_secure_esc_6s_50a_can485_faraday_sameend_faceted.kicad_pcb \
    --strip-width 23.0 --gap 3.0 \
    --json kicad/placement.json
```

KiCad **9.0.2** only — see
[`docs/solutions/architecture-patterns/pcbnew-bulk-removal-segfault.md`](../../../../docs/solutions/architecture-patterns/pcbnew-bulk-removal-segfault.md)
for a pcbnew scripting trap this tool works around (bulk zone/track/drawing
removal segfaults at process exit on this binding unless handled correctly
— the tool handles it; know this before writing a similar script by hand).
