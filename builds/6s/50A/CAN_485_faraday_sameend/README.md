## 1. What "same-end, opposite faces" means here

All five 50 A conductors leave the same board end, for a pocket (blind-cavity)
installation with no access to the far end. The two groups are separated by
putting them on **opposite faces** with the board's two inner GND planes
between them:

| Conductor | Net | Face | Position |
| --- | --- | --- | --- |
| `PH_A` | phase A | F.Cu | (25.45, 90.50) mm |
| `PH_B` | phase B | F.Cu | (35.95, 90.50) mm |
| `PH_C` | phase C | F.Cu | (46.45, 90.50) mm |
| `VM` (VBATT+) | pack + | **B.Cu** | (30.95, 90.50) mm |
| `GND` (VBATT−) | pack − | **B.Cu** | (40.95, 90.50) mm |

Rationale, coupling arithmetic, and the rejected alternatives are in
[`docs/design-single-end-wire-egress-variant.md`](../../../../docs/design-single-end-wire-egress-variant.md).

## 2. The board is longer, not re-partitioned

The design document's original plan moved `U1`/`U2`/`J1` to the logic end to
free the terminal end. **That plan is dead.** `U1`'s courtyard measures
13.45 mm, not the 12.90 mm the envelope calculation assumed, so with `U1` at
the logic end `docs/tools/isolation_envelope.py` returns:

```text
13.45 + 2 x (7.5 + 1.43) + 2 x 0.55 = 32.41 mm minimum board width
```

against an actual 32.00 mm — a **0.41 mm failure**. The 7.5 mm creepage
underneath it is REFERENCES.md [9] Table 6, a verified primary-source value,
so the board width cannot absorb it. The design document's own instruction for
this case is explicit: *"this variant needs a different partition, not a wider
board."*

The different partition is to leave the logic cluster where it is and buy
**length** at the terminal end. `isolation_envelope.py` prices width against
length at 2.7× on this geometry, so length is the cheap dimension.

| | Parent | This variant |
| --- | --- | --- |
| Board outline | 1.260 × 2.602 in (32.00 × 66.10 mm) | 1.260 × 2.996 in (32.00 × 76.10 mm) |
| Board area | 3.28 in² (2115 mm²) | 3.77 in² (2435 mm²), **+15.1 %** |
| `U1` / `U2` / `J1` | B.Cu, y ≈ 76–86 mm | **unchanged** |
| MCU → gate-driver run | ≈18.5 mm | **unchanged** |
| Current-sense returns | — | **unchanged** |

Leaving the logic cluster alone also drops both regressions the original
partition carried.

Applied by [`kicad/tools/make_same_end_egress.py`](kicad/tools/make_same_end_egress.py).

## 3. Inner planes are the interface shield

At the terminal end `In1.Cu` and `In2.Cu` are both solid GND, so two grounded
planes lie between the phase pads on F.Cu and the pack pads on B.Cu. A
grounded plane does not attenuate the field between two conductors — it
terminates it.

This only works because the inner-layer copper-pour keepout was removed from
the parent build first (commit `4baa178`,
[`../CAN_485_faraday/kicad/tools/restore_inner_planes.py`](../CAN_485_faraday/kicad/tools/restore_inner_planes.py)).
Before that, the rule area forbade pour on **all four** copper layers across
the terminal window, so the shield had a hole in it exactly where this variant
needs it. Probe points inside the window went 0/6 → 6/6 in copper on both
inner planes.

## 4. Open: VM distribution to the relocated pack pad

**Two nets at the new terminal end are unconnected, both known and neither
bridged by guesswork.**

| Net | Pad | Why |
| --- | --- | --- |
| `VM` | `J5A` pin 1 | The VM pour stops at y 60.3 mm (F.Cu) and y 60.5 mm (In2.Cu); B.Cu from y 60.5 mm to the board end is GND. Carrying VM to a B.Cu pad in the new terminal band re-partitions a plane, which depends on a stackup this board does not have (§5). |
| `GND` | `J5B` pin 1 | The outer-layer rule area moved with the terminal band and now blocks the B.Cu GND pour from reaching the pad — the same defect `TODO.md` 12.5.an measures on the parent, where pour meets a J4 pad over 1.00 mm of a 10 mm pad. |

Neither was closed with a track. `docs/tools/conductor_sizing.py` shows a
0.118 in (3.0 mm) track across that span costs 11.36 W across three phases —
more than all six TPHR8504PL FETs' 10.5 W conduction loss combined. That
copper must be pour, or the terminal must sit on the pour's layer.

Both point at the same unresolved decision: `TODO.md` 12.5.ae, whether the
outer-layer (F.Cu/B.Cu) extent of the rule area should be deleted or shrunk.
That moves 50 A current paths and is reserved for sign-off. **This build
inherits that open decision from its parent.**

## 5. Open: the board has no stackup

The `.kicad_pcb` declares four copper layers and carries `(thickness 1.6)` in
its `general` block, which is KiCad's default rather than a design decision.
No dielectric height, copper weight, laminate permittivity or surface finish
is specified anywhere in this repository. Tracked as `TODO.md` 15.2; it gates
the copper-weight and fabrication decisions.

traced to fiducials `FID3`/`FID6`, which sat inside the old rule-area band and

step 6 of the tool does this and the errors are gone.

**Routing is not complete on either build** — 150 unconnected items is
inherited, not caused by this variant. This build is not a routed board and
must not be read as one.
